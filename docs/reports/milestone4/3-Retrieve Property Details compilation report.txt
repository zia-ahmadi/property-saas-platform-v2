1. Objective
The objective of this task was to implement a secure REST API endpoint that allows authenticated organization members to retrieve the complete details of an individual property.

The implementation needed to support multi-tenant isolation, enforce organization membership, return the existing standardized property response, and handle invalid or unauthorized requests appropriately.

3.2 Service layer
File: property/service/PropertyService.java

Implemented:
@Transactional(readOnly = true)
public PropertyResponse getProperty(
        UUID organizationId,
        UUID propertyId
) {
    contextResolver.resolve(organizationId);

    Property property = propertyRepository
            .findByIdAndOrganizationId(propertyId, organizationId)
            .orElseThrow(() -> new ResponseStatusException(
                    HttpStatus.NOT_FOUND,
                    "Property not found"
            ));

    return toPropertyResponse(property);
}


The service first validates the authenticated organization's context, then retrieves the property using both its ID and organization ID.

The operation is read-only and reuses the existing DTO mapping.

4. Security and Tenant Isolation
The endpoint uses the existing JWT authentication and organization-context resolution infrastructure.
Scenario	HTTP status
Authorized organization member retrieves an existing property	200 OK
Property does not exist	404 Not Found
Property belongs to another tenant, but the requested organization is accessible	404 Not Found
User lacks access to the requested organization	403 Forbidden
JWT is missing	401 Unauthorized
Property ID is malformed	400 Bad Request

The organization context is validated before the property lookup, and the repository query is tenant-scoped.

This prevents an authenticated member of one organization from retrieving another organization's property through the API.

Both OWNER and STAFF roles were verified to have read access.
