Milestone: 4 — Property Management

The Archive Property feature enables authorized organization members to archive existing properties without permanently deleting their records.

The implementation follows the application's multi-tenant architecture, using organization-scoped property retrieval, role-based authorization, transactional persistence, and an idempotent archive operation.

The feature was verified through 12 dedicated integration tests and a complete regression test suite containing 132 tests.

3. Functional Implementation
3.1 Property Entity
File: property/entity/Property.java

Implemented the archive() method to transition a property's status from ACTIVE to ARCHIVED.

The method is idempotent: archiving an already archived property leaves its status unchanged.

The property record, its organization relationship, and its existing details are retained.
3.2 Property Service
File: property/service/PropertyService.java

Implemented archiveProperty(UUID organizationId, UUID propertyId).

The service performs authenticated organization context resolution, verifies the PROPERTY_MANAGE permission, retrieves the property using both its ID and organization ID, invokes the entity's archive operation, and flushes the change to the database.

The operation is transactional and returns the updated property response.
3.3 REST Controller
File: property/controller/PropertyController.java

Implemented the following endpoint:
PATCH /api/v1/organizations/{organizationId}/properties/{propertyId}/archive


A successful request returns HTTP 200 OK and a PropertyResponse containing the property's ARCHIVED status.

The endpoint does not require a request body.
4. Security and Tenant Isolation
The archive operation applies two authorization boundaries.

First, the authenticated organization context is resolved and the user's PROPERTY_MANAGE permission is checked.

Second, the property is retrieved using an organization-scoped repository query:
findByIdAndOrganizationId(propertyId, organizationId)


This prevents an authorized user in one organization from archiving a property belonging to another organization.

A property that does not exist within the requested organization produces HTTP 404 Not Found.
5. Database Implementation
The existing properties table already supports the archive lifecycle.

The status column permits the values active and archived, and PropertyStatusConverter handles conversion between Java enum values and database values.

No new Flyway migration was required.

The database schema remains at version 3, with all three migrations successfully validated during testing.

Archiving does not delete a property or modify its ownership relationship.
