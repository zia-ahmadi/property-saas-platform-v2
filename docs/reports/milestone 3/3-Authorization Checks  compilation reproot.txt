## 1. Objective

Implement and verify secure, role-based authorization for organization resources in a multi-tenant SaaS application.

The authorization system must ensure that authenticated users can access only the resources of organizations to which they belong and can perform only operations permitted by their assigned roles.

## 3. Authorization Architecture

Authorization is implemented through multiple cooperating components.

### 3.1 Spring Security

**File:** `config/security/SecurityConfig.java`

Responsibilities:

- Enforce stateless authentication.
- Validate JWT access tokens.
- Allow unauthenticated access to registration, login, and refresh-token endpoints.
- Require authentication for all other endpoints.

### 3.2 Authenticated Organization Context

**File:** `organization/context/AuthenticatedOrganizationContextResolver.java`

Responsibilities:

- Identify the authenticated user.
- Resolve the user's membership in the requested organization.
- Validate the membership, user, and organization statuses.
- Reject requests without a valid, active organization membership.

### 3.3 Organization Authorization Service

**File:** `organization/permission/service/OrganizationAuthorizationService.java`

Responsibilities:

- Retrieve organization membership information.
- Validate active membership, user, and organization statuses.
- Evaluate permissions against the membership role.
- Return authorization decisions through `hasPermission()`.
- Enforce permissions through `requirePermission()`.
- Throw `AccessDeniedException` when authorization fails.

### 3.4 Current User Authorization Service

**File:** `organization/permission/service/CurrentUserAuthorizationService.java`

Responsibilities:

- Retrieve the currently authenticated user's identity.
- Delegate authorization decisions to `OrganizationAuthorizationService`.
- Provide permission-enforcement methods for business services.

### 3.5 Organization Service

**File:** `organization/service/OrganizationService.java`

The `getOrganization()` operation performs authorization before retrieving organization information.

Execution sequence:

1. Resolve and validate the authenticated organization's context.
2. Require `ORGANIZATION_VIEW` permission.
3. Retrieve the requested organization.
4. Return the organization response.

This prevents unauthorized organization retrieval through the implemented service operation.

## 4. Role-Based Access Control

The application defines four organization roles:

- OWNER
- ADMIN
- MANAGER
- STAFF

Permissions are centrally defined in `RolePermissionMapping.java`.

### Permission Matrix

| Permission | Owner | Admin | Manager | Staff |
|---|---|---|---|---|
| ORGANIZATION_VIEW | Yes | Yes | Yes | Yes |
| ORGANIZATION_MANAGE | Yes | Yes | No | No |
| MEMBERSHIP_MANAGE | Yes | Yes | No | No |
| PROPERTY_VIEW | Yes | Yes | Yes | Yes |
| PROPERTY_MANAGE | Yes | Yes | Yes | No |
| LEASE_MANAGE | Yes | Yes | Yes | No |
| BILLING_MANAGE | Yes | Yes | No | No |
| MAINTENANCE_MANAGE | Yes | Yes | Yes | Yes |

The OWNER role receives all permissions defined in the `OrganizationPermission` enumeration.

Authorization follows a default-deny approach: users are granted access only when the required conditions are satisfied.

## 5. Security Rules

The authorization implementation enforces the following conditions:

1. The user must be authenticated.
2. The user must have a membership in the requested organization.
3. The membership must be ACTIVE.
4. The user account must be ACTIVE.
5. The organization must be ACTIVE.
6. The user's role must include the required permission.

Requests that fail authorization are denied.
