1. Objective
Implement a secure, tenant-isolated property update API for the Multi-Tenant Property Leasing, Billing, and Maintenance SaaS.

The feature allows authorized organization members to modify selected property attributes while preserving ownership, identity, and other protected fields.
2. Implemented API
Endpoint
PATCH /api/v1/organizations/{organizationId}/properties/{propertyId}
Authorization: Bearer <access_token>
Content-Type: application/json


Example request:
{
  "name": "Updated Kabul Property",
  "city": "Herat",
  "addressLine2": null
}


Successful response: 200 OK, returning the updated PropertyResponse.

The implementation uses partial-update semantics: omitted fields remain unchanged, while an explicit JSON null clears the optional addressLine2 field.

4. Business Rules and Security
The update API enforces the following requirements:
- Tenant isolation: A property is retrieved using its ID and the authenticated organization's ID.
- Authorization: Updating requires the PROPERTY_MANAGE permission.
- Field restrictions: Only approved property attributes may be modified.
- Ownership protection: Clients cannot change organizationId.
- Validation: Empty updates, unsupported fields, and invalid values are rejected.
- Persistence: Valid changes are committed through the transactional service.
The permitted update fields are name, propertyType, addressLine1, addressLine2, city, and countryCode.

Property IDs, organization ownership, status, and audit timestamps are not directly editable through this endpoint.
